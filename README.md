# Route Codex Work

Навык помогает Codex найти нужные исходники, выбрать достаточную глубину работы и выполнить подходящую проверку без чтения всего репозитория. Он также помогает по запросу собрать короткую карту проекта и убрать повторяющиеся инструкции.

**English summary:** A portable Codex skill for focused repository navigation, risk-based task routing, targeted verification, and configurable model effort. It does not alter permissions, billing, automation, or production systems.

## Установка

Через доступный в Codex установщик навыков:

```text
Use $skill-installer to install route-codex-work from
https://github.com/registran4ik/codex-work-routing/tree/main/skills/route-codex-work
```

Либо скачайте репозиторий и поместите папку `skills/route-codex-work` в каталог пользовательских навыков, настроенный в вашем Codex (например, `$CODEX_HOME/skills`). При существующей одноимённой папке сначала сравните изменения и сохраните свою версию. Откройте новый чат или обновите обнаружение навыков способом вашего клиента.

Пакет не содержит установочного скрипта и не меняет `config.toml`, модель текущего чата, Fast, права доступа или таймеры.

## Использование

```text
Используй $route-codex-work: для этой задачи найди нужные файлы,
существующий механизм, минимальную проверку и достаточный уровень усилий.
```

Для отдельной работы над навигацией:

```text
Используй $route-codex-work. Обнови существующую карту проекта и AGENTS:
реальные точки входа, маршруты задач и тестов, чувствительные границы.
Продуктовый код не меняй. Проверь карту на десяти реальных типовых запросах.
```

L0–L4 описывают риск, неопределённость и связи задачи. Однострочная правка прав доступа может требовать L3, а опечатка на странице входа — L0. Уровень не является разрешением изменить всю подсистему.

Имена моделей задаются вашим профилем и доступностью клиента. Примерный старт: low для механики, medium для локальной функции, high для цепочки компонентов, более глубокое рассуждение для чувствительного изменения. Ultra имеет смысл при полезных независимых частях и разрешённом делегировании; навык не обещает преимущество по качеству или времени. Fast и service tier остаются под управлением пользователя.

## Что внутри

- [SKILL.md](skills/route-codex-work/SKILL.md) — короткий рабочий вход.
- [Карта репозитория](skills/route-codex-work/references/repository-mapping.md) — как установить настоящие границы и команды.
- [Профили моделей](skills/route-codex-work/references/model-profiles.md) — выбор effort, ограничения квоты и наблюдаемая настройка.
- [Поведенческие проверки](skills/route-codex-work/references/behavioral-checks.md) — сценарии для проверки маршрутизации.

Не требуется создавать двадцать документов или запускать дополнительные модели. Команда с отметкой FOUND лишь найдена; VERIFIED требует реального исполнения. Общий процент подписочной квоты не является стоимостью конкретной задачи. Синтаксическая проверка навыка не заменяет проверку поведения в вашем проекте.

Это авторская практическая схема, не официальный продукт OpenAI и не сравнительный benchmark. Изменения доступности моделей проверяйте по [официальной документации](https://learn.chatgpt.com/docs/models). Основы выборочного чтения описаны в [рекомендациях по навыкам](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra).

## Проверка и изменения

Если в установленном Skill Creator есть `quick_validate.py`, запустите его для папки навыка. Затем проверьте реальные запросы вашего проекта по поведенческим сценариям. Сообщая проблему, приложите обезличенный запрос, ошибочный маршрут, ожидаемую проверку и версию клиента; не прикладывайте секреты, рабочие базы и частную переписку.
