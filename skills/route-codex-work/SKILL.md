# Route Codex Work

Choose a useful outcome, a bounded surface, and sufficient verification. This skill routes work; it does not grant access, change account settings, start automation, or authorize publication.

## Route a task

1. Preserve the user's current objective and explicit model, effort, pause, and permission choices. Identify the expected result, allowed surface, and one acceptance check. For a small task, one sentence is enough.
2. Read the applicable entry instructions and the existing map's relevant row. Follow actual imports, route registration, asset wiring, or callers when the boundary is unclear. Search the named paths first. Do not load archives or every domain document.
3. Choose the lowest sufficient level below. Raise it only for observed risk, ambiguity, dependencies, or difficult recovery. File count, urgency, and model name do not determine the level.
4. Find the existing abstraction and its test before adding a new layer. Apply the established local pattern. Preserve unrelated working-tree changes.
5. Run the smallest meaningful check for the changed behavior, then a real user-path smoke when required and available. Broaden testing only for shared impact or unresolved evidence. Report the artifact, actual check, and remaining limitation.

| Level | Evidence about the task | Reading and verification |
|---|---|---|
| L0 | Mechanical change with known local effects | Exact fragment; relevant local check |
| L1 | A local behavior in one established component | Component and caller/test; targeted behavior check |
| L2 | A connected change across components | The affected data flow and existing contracts; boundary test |
| L3 | Identity, permissions, money, schema, shared runtime, or hard rollback | Impact and failure cases; explicit validation and recovery approach |
| L4 | Broad change across several domains or a major uncertain redesign | Bounded phases, dependency map, integrated acceptance; parallel independent work only when allowed and useful |

A typo in an authentication page can remain L0; a one-line authorization bypass is L3. A large generated output can have low reasoning complexity but still require verifying its generator. Classification limits investigation; it is not permission to change the whole named domain.

## Choose effort separately

Use the environment's available model catalogue and the user's configured profile. A starting effort ladder is low / medium / high / deeper reasoning for L0 / L1 / L2 / L3. L4 may benefit from a capable orchestration mode when useful independent parts exist; sequential hard work may instead need one stronger reasoning run. These are adjustable starting points, not performance guarantees.

Read [model profiles](references/model-profiles.md) when selecting or revising a profile, handling a limit, or interpreting runtime settings. Do not read it for every text edit. Speed/service tier remains user controlled unless explicitly authorized otherwise. Quota percentage is account-level evidence, not task cost.

## Build or repair a repository map

Only when requested, read [repository mapping](references/repository-mapping.md). Reuse the current documentation structure. A short entrypoint, a combined task/test map, and a few conditional details often suffice. Do not generate a fixed collection of documents, nested instructions, wrappers, or hypothetical execution plans.

Validate routing with realistic requests using [behavioral checks](references/behavioral-checks.md). A validator or link check establishes structure, not behavioral quality or product readiness. Preserve exact before/after changes when replacing established instructions.

## Stop and uncertainty rules

- Follow the existing task's retry limit and direct exceptions; keep its used attempts and evidence. A new model, chat, filename, or context reset does not reset a repair.
- After failure, distinguish product, fixture, tool, access, and unknown causes. Get new evidence or make a causal change before repeating. Do not schedule a reviewer cascade by default.
- An external write with unknown outcome needs readback before retry. Successful rollback does not prove the original cause, but it can establish the final state.
- Respect explicit pauses and actual tool refusals. Prepare the authorized independent work before asking for missing permission; do not ask again for permission already granted.
- One writer owns each shared file set, process, database, or release. Delegation follows the current environment and explicit user constraints; a skill is not authority to message people, create chats, or call external models.
- Permission to publish a reusable package does not authorize disclosing private source material. Inspect the exact export for private content before publication.
