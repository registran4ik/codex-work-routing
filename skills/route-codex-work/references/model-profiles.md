# Configurable model and effort profiles

Model availability, supported effort levels, and billing change. Use the catalogue and runtime evidence of the current environment. Do not treat a benchmark, marketing name, or this table as an evergreen guarantee.

## Profile, not automatic configuration

Keep the profile in the user's existing settings or task policy; do not create another registry. Useful fields are preferred general model, permitted alternatives, high-uncertainty model, supported efforts, delegation limit, speed-control owner, and explicit exceptions. Names are supplied by the user/environment rather than hardcoded in this skill.

| Work | Initial choice | Upgrade trigger |
|---|---|---|
| Deterministic extraction/transformation | Ordinary tool; no model call if unnecessary | Interpretation cannot be encoded reliably |
| Mechanical/local known edit | Suitable available model, low effort | Unclear effect or sensitive boundary |
| Local implementation | Preferred model, medium effort | Cause spans callers or requirements conflict |
| Connected feature/diagnosis | Preferred model, high effort | Hidden interactions or hard recovery |
| Sensitive/architectural work | Capable model, deeper supported effort | Remaining uncertainty justifies more reasoning |
| Several independent substantial parts | Capable orchestrator if allowed/useful | Explicit surfaces and integration check are ready |

A permitted lighter model can suit mechanics, but urgency alone does not make it adequate for authorization, payments, migrations, or release integrity. Record the reason for a meaningful exception and its acceptance check. An explicit fixed assignment remains until the user or applicable policy permits changing it. Do not silently substitute an unavailable model.

More effort can take more time and tokens; it does not guarantee a better result. Max and orchestration modes solve different needs. Ultra can use subagents for independent parts; do not claim it always delegates, always wins, or is an API reasoning level. Follow the actual client and available tools. Do not transfer web behavior to a local client without verification.

## Runtime evidence and delegation

Requested settings, saved preferences, and observed model/effort for a particular turn are distinct. A delivered message to an active task may steer its input without changing that turn's model. Use real supported controls at the next authorized working boundary, then check the relevant metadata if available. If not observable, record unknown. Do not wake a paused task or run an empty turn merely to prove a setting changed.

Use delegation only when the current environment and user constraints allow it and the benefit exceeds packet preparation/integration. Assign an independent outcome, exact writable surface, and acceptance check. A shared database/process/release remains one writer even if file paths differ. Nested agents count toward the configured total. Do not equate every difficult task with parallel work or start external models/accounts because a helper is unavailable.

An error can require a missing observation rather than a stronger model. Preserve previous attempts, distinguish infrastructure/fixture failures, and use the agreed retry/audit procedure. Raise effort or ask a stronger permitted model only with a concrete reason. A second opinion is not a fresh permission or a new attempt budget.

## Limits and costs

Use only real available quota information. Account usage percentage is not the cost of a specific task, model, or money spent; concurrency and rounding defeat that attribution. Unavailable readings are unknown. API prices and subscription quota are different measures. Compare accepted outcomes on similar tasks with disclosed sample size, retries, and wait time rather than relying on fixed percentages for a work mix.

Honor the user's configured thresholds, manual overrides, and later explicit exceptions. Do not invent numeric thresholds in a new project. If a stop is required, finish or reconcile the current atomic operation safely, preserve work and unknown outcomes, then pause the covered agents. A pause of coding agents need not stop product services. Resume only under the existing user rule; a quota reset alone is not permission. Speed/Fast/service tier is user controlled unless specifically authorized, independently from model effort. Do not change billing, buy credits, or use paid fallback routes implicitly.
